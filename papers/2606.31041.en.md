# Semantic-Layer-Mediated Agent: Separate Business Semantics from Physical SQL

[中文](2606.31041.md) | **English** · [Home](../README.en.md) · [Research Library](../library/README.en.md)

[Paper](https://arxiv.org/abs/2606.31041) · **Importance: 4/5**

> **Research delta.** The design gives the LLM responsibility for composing verified business concepts in a curated semantic layer, then delegates physical-schema and SQL-dialect realization to deterministic compilation.

## Problem

Direct NL→SQL over large enterprise schemas asks one model to solve business-semantic grounding, schema linking, join selection, and dialect-specific SQL generation at once. When it fails, semantic and physical-execution errors are difficult to separate.

## Mechanism

`user intent → semantic-layer grounding → Semantic Model Query → deterministic compiler → physical SQL → execution`

The intermediate semantic representation narrows the model’s job to business-level composition while reusing conventional deterministic database machinery downstream.

## Closest comparison

The meaningful controls are direct NL→SQL over the raw schema and metadata/RAG-assisted agents without an explicit semantic IR. Better results cannot be attributed entirely to the agent: the semantic layer itself contains curated system knowledge.

## Decisive evidence

The main research value is **factorization**. Separating semantic correctness from SQL realization provides a clearer failure boundary and constrains the generation space with reusable business definitions.

## What remains unproven

The cost moves upstream into semantic-layer creation and maintenance. How much coverage is required? What happens when definitions are incomplete, stale, or wrong? A decisive evaluation should report curation/coverage cost and compare graceful degradation under full, partial, and absent semantic layers.

## Field-map consequence

This creates an explicit boundary:

`natural-language intent → semantic/intermediate plan → physical execution`

which is more informative than treating all progress as Text-to-SQL model accuracy.
