# SkillEffect: Lower Data Programs into Bounded Execution Before Dispatch

[中文](2608.17007.md) | **English** · [Home](../README.en.md) · [Research Library](../library/README.en.md)

[Paper](https://arxiv.org/abs/2608.17007) · **Importance: 4/5**

> **Research delta.** SkillEffect does not grant a model-generated program execution authority directly. At tool dispatch, it rebuilds a constrained intermediate representation and invokes an audited bounded implementation, turning memory obligations into checkable preconditions.

## Problem

An agent-generated pandas, XLSX, or Top-k program can be semantically correct yet load the entire input and fail under a hard per-call memory cap. Prompting the model to “stream” does not ensure that the submitted code obeys the resource constraint.

## Mechanism

Each supported computation registers a relation plugin that recognizes source programs, extracts facts from immutable input, constructs a bounded IR, computes an arena bound, and declares a postcondition. An independent checker reconstructs these relations from the submission. Only then does the shared runtime issue an atomic capacity lease, run the bounded VM, and publish output after checking the postcondition.

The boundary is:

`agent program → recognize relation → rebuild bounded IR → reserve capacity → audited execution → verify → publish`

The architecture is reusable, but coverage is not automatic: every new relation still requires a manually authored and audited plugin.

## Closest comparison

The physical experiments compare eager direct execution with an audited bounded implementation under the same task, input, verifier, and cgroup cap. This answers whether bounded access completes under the same external memory limit. It does not attribute the gain to the checker, lease, or publication gate; the paper calls this an operator-characterization reference.

A simpler deployment alternative is a typed bounded-tool API. The paper shows that where the platform owns the tool surface, this can provide the same bounded execution without recognizing arbitrary source programs.

## Decisive evidence

- Twenty-four task–Skill pairs cover six operator families. The hard-cap sweep has **1,296 cells**: 1,116 executions and 180 abstentions. Bounded access uses **3.75–24.25×** less peak memory than eager execution, with an **8.45×** median.
- Across the same cap levels, direct completion is **0 / 0 / 4 / 20 / 20 / 24 of 24**; bounded completion is **12 / 24 / 24 / 24 / 24 / 24**.
- On the nine tasks where composition already produces a correct bounded plan, both paths have cap AUC **0.956**. Extra coverage comes from other registered relations, not better execution on the shared subset.
- Among 72 natural-language plans, 25 verifier-valid attempts cover only 10/24 tasks. Lowering moves those tasks from **5/10 direct success to 10/10**, with 30/30 lowered repeats.
- The checker accepts **60/60** legal configurations and rejects **500/500** constructed mutations. These are predefined mutation classes, not an open-world deployment error distribution.

## Cost and failure boundary

The XLSX plugin requires about **476 lines of relation-specific code**. Certification and execution take about 41.70 and 41.59 seconds because each scans the workbook, nearly doubling scan work. Capacity reservations have 44.7% median and 99.3% maximum overhead. Model-GPU cost, plugin-audit labor, and remote side effects are outside the budget.

Even with 48/48 verified tool executions, the external harness produces strict final JSON in only **13/16** cases. Resource-safe execution therefore does not establish artifact correctness or delivery quality.

## Claim ceiling

For six manually audited, deterministic, local read-only data-tool relations, checked dispatch can replace recognized eager programs with semantically checked bounded implementations and improve completion under tight memory caps. It does not automatically optimize arbitrary agent code.

## Field-map consequence

This is an `early_signal` in **Execution & Transformation**. It inserts a resource-verification boundary between code generation and execution authority, but one paper does not change the stable map.
