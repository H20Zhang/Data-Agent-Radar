# AgentSM: Persist Database-Specific Execution Knowledge as Semantic Memory

[中文](2601.15709.md) | **English** · [Home](../README.en.md) · [Research Library](../library/README.en.md)

[Paper](https://arxiv.org/abs/2601.15709) · **Importance: 4/5**

> **Research delta.** AgentSM turns successful database execution experience into interpretable semantic programs that can be retrieved and adapted later, rather than treating every new query as a cold start or storing only raw SQL demonstrations.

## Problem

Agents repeatedly working on the same database rediscover join paths, business concepts, filters, and execution corrections. Raw trajectories are long and query-specific; raw SQL examples preserve syntax but may hide the reusable reasoning pattern.

## Mechanism

`successful execution trace → extract/normalize semantic program → persistent semantic memory → retrieve relevant prior program → adapt to current query → execute/verify`

The memory is intended to preserve database-specific procedural/semantic knowledge while removing some query-specific noise.

## Closest comparison

The useful controls are:

`no memory` vs `raw demonstration retrieval` vs `trajectory summary` vs `semantic-program memory`

under the same database, retrieval budget, and actor context. Any extra model or curation used to construct the semantic program should be charged separately.

## Decisive evidence

The important research signal is longitudinal: execution experience can become reusable state that changes future query processing, rather than being discarded after each task.

## What remains unproven

Schema, business logic, data distribution, and tool behavior drift. Old semantic programs can become stale priors. A mature system therefore needs versioning, conflict detection, utility attribution, and explicit update/deletion policy—not only retrieval.

## Field-map consequence

Data-agent learning and reuse should include:

`execution experience → persistent interpretable memory → future workflow reuse`

This overlaps with procedural memory research, but the database-specific failure mode is schema/tool/business-logic drift.
