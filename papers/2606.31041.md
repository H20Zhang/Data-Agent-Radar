# Semantic-Layer-Mediated Agent：让 LLM 处理业务语义，让 Compiler 处理 Physical SQL

**中文** | [English](2606.31041.en.md) · [返回首页](../README.md) · [Research Library](../library/README.md)

[Paper](https://arxiv.org/abs/2606.31041) · **Importance: 4/5**

> **Research delta.** 这项设计把 enterprise NL→SQL 拆成两个责任边界：LLM 在 curated semantic layer 上组合 business concepts，产生 compact Semantic Model Query；deterministic compiler 再把它落到具体 physical schema 与 SQL dialect。

## Problem

Large enterprise database 往往有大量表、命名历史、dialect 差异与隐含 business definitions。让 LLM 直接从自然语言一步生成 physical SQL，等于同时承担：业务语义 grounding、schema linking、join/path selection 与 dialect realization。

错误一旦发生，很难判断究竟是“业务概念理解错”还是“SQL realization 错”。

## Mechanism

`user intent → semantic-layer grounding → Semantic Model Query → deterministic compilation → physical SQL → execution`

LLM 主要处理更接近业务层的概念组合，compiler 负责已定义 semantic object 到 physical database 的映射。

## Closest comparison

最合理的 baseline 是 direct NL→SQL over raw schema，以及同样使用 metadata/RAG 但没有 explicit semantic IR 的 agent。

需要注意：semantic layer 本身包含大量人工/系统先验，因此更好的 query correctness 不应全部归因给 agent reasoning。

## Decisive evidence

这项工作的研究价值主要来自 **factorization**：把 semantic correctness 与 physical execution correctness 分离后，系统可以对失败位置做更明确 attribution，也能复用 deterministic database engineering 来约束生成空间。

## What remains unproven

最大成本被移到了 semantic layer：谁来创建和维护 business concepts、joins、metrics 与 dialect mapping？Coverage 不完整时 agent 怎么 fallback？Semantic definition 与实际 data drift 时怎么检测？

最有判别力的实验应同时报告 semantic-layer coverage/curation cost，并比较完整 semantic layer、partial layer、raw-schema agent 的 graceful degradation。

## Field-map consequence

它强化了 Data Agent 的一个独立 boundary：

`natural-language intent → semantic/intermediate plan → physical execution`

这比把所有进展继续归入 Text-to-SQL model accuracy 更有研究解释力。
