# StagedWorkspace：让检索视图与原生产物指向同一工作区状态

**中文** | [English](2608.18050.en.md) · [返回首页](../README.md) · [Research Library](../library/README.md)

[Paper](https://arxiv.org/abs/2608.18050) · **Importance: 4/5**

> **Research delta.** StagedWorkspace 把原生文件视为权威工作区状态，同时向 Agent 暴露 parsed retrieval view、native artifact 与 review diff，并用内容哈希标记它们所对应的版本。

## Problem

知识工作 Agent 会搜索解析文本、编辑原生文档、查看改动并提交最终产物。如果这些界面引用不同版本，Agent 可能依据旧解析结果修改新文件，或在没有看见真实 diff 的情况下交付错误 artifact。

## Mechanism

系统把原生 workspace 记为权威状态 `W_t`。解析记录携带 content hash，可被标为 current 或 stale；Agent 可以同时使用适合定位的 parsed view 和适合真实执行、视觉检查的 native view。编辑后的 diff 作为 review surface 暴露，再进入提交。

可以把闭环写成：

`native state → parsed localization → native execution/edit → diff review → submitted artifact`

## Closest comparison

read-axis ablation 固定 model、prompt、parser、retriever、grader、file tracker 与 250-call budget，只比较 dual view、artifact-only 和 parsed-only。这个设计能隔离“同时拥有两个 access surfaces”的价值。

它没有隔离 content-hash synchronization：OfficeQA 是静态只读任务，论文也没有 synced-vs-unsynced 或 versioned-vs-unversioned 对照。因此不能把 dual-view 收益归因给版本绑定本身。

## Decisive evidence

- OfficeQA Pro 有 **133 questions**。dual 相对 artifact-only 的 Pass@1 提升为 **+12.1 / +10.1 / +8.3 个百分点**，paired-bootstrap half-width 为 7.6 / 7.2 / 7.9，p=.005 / .010 / .041。
- APEX-Agents 纳入 **452/480 tasks**，排除 28 个 API-dependent tasks。dual 相对 parsed-only 的 mean-rubric 提升为 **+4.7 / +5.5 / +9.2**，half-width 为 3.2 / 3.9 / 5.9，p=.014 / .028 / .0002。
- APEX 中 dual 相对 artifact-only 只高 +1.0–4.0，三种模型均未达到 p<.05；**188/452** tasks 在所有 arms 都为零分。
- review-axis 只覆盖 **57 个 file-editing tasks**，diff-visible 的点估计提高 +2.5 / +8.5 / +3.8，但没有置信区间或 p 值，只能作辅助证据。

## Cost and failure boundary

论文报告的 API 成本没有包含 Reducto / Mistral ingestion、后台 parsing、sandbox CPU 与 startup。production implementation 未公开；计划发布的是 sanitized code。定性机制标签来自人工 trace coding，但没有 annotator 数量或一致性。

更重要的是，grader 没有直接评分 workspace state transition 是否正确。dual access 可以提高 benchmark outcome，却仍可能在状态同步、编辑过程或最终 artifact 上失败。

## Claim ceiling

在固定 SW-Agent harness 中，同时暴露 parsed search 与 native artifact，在 133 个 OfficeQA questions 和 452 个 APEX tasks 上优于更受限的 single-view arm。这个结果支持 dual access，而不是 content-hash versioning 的因果效果。

## Field-map consequence

该工作作为 `early_signal` 进入 **Execution & Transformation**。它把中间状态和交付产物放入同一工作区契约，但单篇论文、且未隔离版本绑定，尚不足以修改稳定地图。
