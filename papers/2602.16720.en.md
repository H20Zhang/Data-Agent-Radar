# APEX-SQL: Turn Schema Linking into Hypothesis → Profiling → Verification

[中文](2602.16720.md) | **English** · [Home](../README.en.md) · [Research Library](../library/README.en.md)

[Paper](https://arxiv.org/abs/2602.16720) · **Importance: 4/5**

> **Research delta.** APEX-SQL treats schema grounding as an active evidence-acquisition problem: the agent inspects real values and distributions to verify column, join, and value hypotheses before generating SQL.

## Problem

Enterprise column names and descriptions often under-specify real semantics. Similar fields can use different grains, units, or encodings; plausible joins may have little value overlap; a user-mentioned entity may not occur in the guessed column.

A metadata-only agent can therefore produce syntactically valid but semantically wrong SQL after one early grounding mistake.

## Mechanism

`question → candidate schema hypothesis → profile/query real data → inspect values/distributions/overlap → revise hypothesis → generate/execute SQL`

The database is used as a **grounding tool**, not only as the final execution target.

## Closest comparison

The clean control uses the same base model, schema metadata, and SQL backend but removes active profiling. Extra database calls and tokens must be charged to the exploratory system.

## Decisive evidence

The important systems point is that real data is an information source for schema semantics distinct from column-name or document similarity. Active probes can falsify candidate grounding before expensive downstream execution commits to it.

## What remains unproven

Profiling adds latency, database load, and possible data exposure. Production systems may restrict sampling, distinct-value inspection, or arbitrary exploratory queries. The next step is cost- and permission-aware probing: which probe has the highest information gain under a fixed query/latency budget?

## Field-map consequence

Data discovery should distinguish:

`static metadata retrieval ↔ active evidence acquisition from the data itself`

The data source is an executable environment, not merely a document corpus.
