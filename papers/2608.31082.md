# Agentic Data Cracking：把已经付过的文档读取变成跨查询结构资产

**中文** | [English](2608.31082.en.md) · [返回首页](../README.md) · [Research Library](../library/README.md)

[Paper](https://arxiv.org/abs/2608.31082) · **Importance: 4/5**

> **Research delta.** 这项工作的关键不是“再加一个 extraction agent”，而是把一次查询已经支付过的 document prefill 变成共享、持久、可被后续不同查询复用的结构化数据。Agentic Data Cracking 只在回答 Agent 因真实 miss 已经打开文档后 fork 一个 bounded cracking branch，额外抽取带 evidence 的 entity / attribute / relation；后续查询先读这些结构，miss 再回退原文。它给 Data Agent 的 Learning & Reuse 提供了一个新的控制边界：**复用的对象可以不是答案或轨迹，而是 workload 逐步物化出来的 data substrate。**

## Problem

多步 data reasoning 往往不是 decode-heavy，而是反复打开长文档造成的 prefill-heavy workload。Agent 每次需要几个散落事实，却要重新把整篇网页、报告或 PDF 放进上下文；相关查询如果持续命中同一批文档，这些读取成本会被重复支付。

最直接的两个极端都不理想。提前把整个 corpus 全量结构化会为大量永远不会被查询的实体与关系支付无界 extraction cost；每次查询只临时抽当前所需事实，则无法利用跨查询 locality。论文要回答的是：**能否让真实 workload 决定何时结构化、结构化什么，并把已经付过的读取转成共享资产？**

## Mechanism

Agentic Data Cracking 把读写边界放在一次真实 document miss 之后。主 reasoning agent 先通过 catalog 查询现有 cracked objects；命中时直接读取 compact structured values 和 evidence，避免打开原文；miss 时按普通流程打开文档。

文档进入 context 后，系统从同一个已加载 prefix fork cracking sub-agent。这个分支不只缓存当前查询请求的 fact，而是在固定 **4K output-token budget** 内推测与当前 workload 邻近、可能被后续查询复用的 entity / attribute / relation。输出被限制为 schema-constrained JSON，并经过 normalization、grounding 与 invariant checks 后写入共享 store。每条 cracked object 都保留 source/evidence region；list-valued relation 只有完整提取时才允许复用。miss 始终可以退回 raw document，因此结构层不是 correctness-critical 的唯一数据源。

## Closest comparison

论文最重要的 matched control 是原始 FanOutQA agent：两边使用同一个 Claude-Haiku-4.5、FanOutQA instructions / prompts / filesystem tools，并都开启 prompt caching；实验条件的主要区别是 cracking instructions 以及 structured read/write interface。这个对照能回答“增加一个持久结构化复用层后，完整系统的 token / API cost 是否下降”。

但它没有隔离更窄的机制 claim。真正需要补的最近简单对照是 **demand-only persistent cache**：只存当前 miss 真正请求的 facts，不做 speculative nearby extraction，并给相同的额外 decode / storage budget。没有这个对照，53% headline 不能被归因于“speculation”本身；它也可能主要来自跨查询持久化和避免 document reopen。

## Decisive evidence

- 为了在 FanOutQA 中制造原 benchmark 缺少的跨查询 locality，作者为每个正式 test question 生成一个“相关但目标属性不同”的 preceding question，并由人工验证。正式指标仍只在原 test questions 上报告。
- 在这个 workload 上，mean prefill 从 **189K 降到 87K tokens**，mean API cost 从 **$0.26 降到 $0.12**，即 headline 约 **53% cost reduction**；LLM-judge accuracy 为 42% vs. baseline 43%，差异不显著（p=.39），word-match accuracy 下降 2pt。
- 4K-token cracking budget 约产生 150 个 cracked objects，并计入完整成本；论文报告该额外 cracking / cache-read 开销约为每题 **12%**。收益并不均匀：paired cost ratio 的 90th percentile 上 cracking 反而是 baseline 的 **1.24× cost**，说明无 reuse 时额外结构化会亏损。
- 在更强 locality 的 Hitchcock case study 中，20 个 warm-up related questions 之后的 10 个 test questions，mean cost 从 $0.81 降到 $0.27。这个结果更像“长期 workload 的上界机会”，而不是独立的通用性证明。

这组证据最强地支持一个系统级判断：当 workload 确实反复触达同一文档并询问不同属性时，把已读取文档中的部分结构持久化，能够用额外 bounded decode 换取未来更少的 raw-document prefill。

## Cost and maintenance boundary

这篇论文比很多 agent-memory / orchestration 工作更值得关注的一点，是它明确把 online token 和 API cost 放进主实验：prompt-cache read、cracking decode 以及无 reuse 时的负收益都没有被藏掉。

但长期维护成本仍没有闭合。当前系统假设 **static corpus**；论文只指出文档变化时可以删除或增量修正相关 cracked objects，并没有测 stale fact detection、revision binding、conflict resolution、global storage growth、catalog lookup overhead 或重新验证成本。企业文档恰恰会发生权限、版本、数字与业务定义变化，因此“结构会随使用越来越值钱”必须同时扣除 invalidation 和 governance cost。

## Skeptical audit

第一，**locality 是实验主动构造的 treatment**。原 FanOutQA 几乎不会重复打开同一文档，作者因此为每个 test question 插入一个专门设计的相关 preceding question，而且 test question 总是在 warm store 上运行。这个设计能测机制在存在 locality 时是否工作，却不能估计真实企业 workload 中 locality 的频率、分布和 break-even point。

第二，matched baseline 隔离的是整个 cracking interface，而不是 speculative policy。系统同时加入共享 store、catalog、structured reads、writes、grounding checks 和 speculative extraction。缺少同预算 demand-only fact cache / non-speculative extraction control，因此不能把系统级 savings 单独记给“agent-discovered semantic speculation”。

第三，accuracy preservation 很大程度来自 conservative raw-document fallback。它说明结构层没有明显破坏当前任务，但也意味着 headline cost gain 同时依赖 miss policy、catalog resolution、prompt caching 和 workload order。对 enterprise data 来说，还需要测错误 structure 被复用后是否改变 later behavior，而不仅是当前 benchmark 最终答案均值近似不变。

## Claim ceiling

现有证据支持：**在作者构造的 related-query locality 下，Data Agent 可以把已经发生的文档读取转成跨查询共享的 evidence-backed structure，并在完整计算 cracking overhead 后显著降低后续 prefill / API cost，同时通过 raw fallback 保持近似回答质量。**

现有证据不支持：speculative cracking 比相同预算的 demand-only persistent cache 更优；53% savings 能外推到未知 locality 的真实企业 workload；也不支持在动态 corpus 中忽略 stale-state、invalidation、权限与维护成本。

## Field-map consequence

该工作以 `early_signal` 进入 **Learning & Reuse**，同时连接 Data Discovery & Grounding。它把复用对象从“历史答案 / workflow memory”扩展到“由 workload 逐步物化的共享数据结构”，但目前只有单篇证据，且 strongest control 仍缺 demand-only cache 与真实 locality / drift 测量，因此不修改稳定 Field Map。
