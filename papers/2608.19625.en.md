# Scientific Data Skills: Package Dataset Knowledge as a Traceable Agent Interface

[中文](2608.19625.md) | **English** · [Home](../README.en.md) · [Research Library](../library/README.en.md)

[Paper](https://arxiv.org/abs/2608.19625) · **Importance: 3/5**

> **Research delta.** SciDSK does not copy the dataset into the agent. It packages the scientific context, file organization, operating procedures, quality checks, and provenance of one dataset snapshot as a routable, reusable skill, moving from “find the data” toward “know how to interpret and prepare it.”

## Problem

Scientific datasets are scattered across repositories and documented for human readers. Even after an agent finds a candidate dataset, it may not know the roles of individual files, how fields map to scientific concepts, what preparation is required, or which constraints come from authoritative sources.

The key boundary is therefore not retrieval recall alone. Dataset identity, a specific snapshot, file-level semantics, and operational guidance must remain traceably connected.

## Mechanism

One SciDSK corresponds to one dataset snapshot while the underlying data remain in the source repository. The `SKILL.md` frontmatter contains a routing description, source, dataset and skill identifiers, license, and snapshot. Its body organizes six components: overview, access, fields and structure, usage guidance, quality checks, and provenance/citation.

The construction path is:

`authoritative sources → normalized facts with attribution → specification-guided authoring → source / structure / package checks → revision and publication`

The Skill Bank adds discovery and downloads across six disciplines, persistent identifiers, and pre-publication review. This is static, versioned reusable state—not memory that learns continuously from use.

## Closest comparison

The discovery experiment compares BM25-Raw, Agent-Raw, Agent-SciDSK-Text treating a full skill as an ordinary document, and Agent-SciDSK registering it as a routable skill. Agent conditions share a budget of at most four searches, ten candidate inspections, and the final-ranking protocol.

The winning condition first selects two disciplines and then searches registered resources, while its search index still uses conventional metadata. Discipline routing, registration, context exposure, and workflow all change together. The missing simple control is an agent with the same two-stage routing, index, budget, and tools but conventional metadata only.

The interpretation experiment also lacks an information-matched control. SciDSK aggregates file facts and checks from multiple sources, while the published result compares it with a ScienceDB page. Putting the same facts in a neutral structured document would be needed to isolate skill packaging.

## Decisive evidence

- The discovery test contains 72 datasets and 104 manually reviewed single-target queries. Agent-SciDSK reports Hit@1 / Recall@5 / MRR / nDCG@5 of **80.77 / 94.23 / 86.41 / 88.40**, versus **70.19 / 90.38 / 79.01 / 81.92** for Agent-SciDSK-Text.
- Agent-Raw and Agent-SciDSK-Text are essentially tied: Hit@1 is **71.15 vs 70.19**, and both have **90.38** Recall@5. This negative result shows no observed benefit from using richer skill text as an ordinary retrieval document.
- File interpretation covers only four selected cases and 24 atomic criteria. SciDSK satisfies **23/24**, compared with **22/24** for a ScienceDB page—a net gain of one criterion.
- In the CT case, the skill distinguishes 196 visible slices from the reported dataset total of 1,576 files and lists continuity, readability, parameter-file, and directory-completeness checks. The representation exposes more specific file guidance, but the experiment does not execute those checks.

## Cost and failure boundary

Cost moves into manual dataset selection; collection of landing pages, file inventories, dictionaries, papers, licenses, and version records; normalization; authoring; repeated review; identifier issuance; and snapshot maintenance. The paper does not quantify author/reviewer labor, update throughput, staleness handling, tokens, tool calls, actual retries, or runtime cost.

The discovery gain may come mainly from two-stage routing rather than skill content. Interpretation criteria directly reward file facts and checklists that humans inserted into the skill; the four cases were selected by the authors, use one blinded evaluator, and have no uncertainty analysis.

Although the paper repeatedly says “invoke,” it does not evaluate data download, preprocessing, downstream analysis, execution of checks, failure recovery, or final scientific claims. It also does not test malicious/conflicting instructions, snapshot drift, or invalidation policy.

## Claim ceiling

Within the July 2026 Skill Bank snapshot, one Qwen harness, and a restricted MCP environment, the registered, discipline-routed SciDSK workflow improves intended-dataset retrieval. In four cases, manually curated skills also provide slightly more file-level interpretation and check guidance.

The evidence cannot attribute the gain to skill content, registration, routing, or version fields individually, and does not demonstrate dataset invocation, executed verification, scientific correctness, recovery, safety, or scalable maintenance.

## Field-map consequence

This is an `early_signal` in **Data Discovery & Grounding**, connected to **Learning & Reuse**: dataset knowledge can become a persistent agent interface with snapshot and provenance bindings. One system-level paper without a matched control does not change the stable map.
