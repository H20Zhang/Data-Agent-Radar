# StagedWorkspace: Keep Retrieval Views and Native Artifacts on One Workspace State

[中文](2608.18050.md) | **English** · [Home](../README.en.md) · [Research Library](../library/README.en.md)

[Paper](https://arxiv.org/abs/2608.18050) · **Importance: 4/5**

> **Research delta.** StagedWorkspace treats native files as authoritative workspace state while exposing parsed retrieval views, native artifacts, and review diffs to the agent, with content hashes identifying their versions.

## Problem

A knowledge-work agent searches parsed text, edits native documents, reviews changes, and submits final artifacts. If those surfaces reference different versions, the agent may modify a new file using stale parsed evidence or deliver a wrong artifact without seeing the actual diff.

## Mechanism

Native workspace `W_t` is authoritative. Parsed records carry a content hash and can be current or stale. The agent can use parsed views for localization and native views for real execution or visual inspection. After edits, a diff becomes a review surface before submission.

The loop is:

`native state → parsed localization → native execution/edit → diff review → submitted artifact`

## Closest comparison

The read-axis ablation fixes the model, prompt, parser, retriever, grader, file tracker, and 250-call budget while comparing dual view, artifact-only, and parsed-only access. It can isolate the value of exposing both access surfaces.

It does not isolate content-hash synchronization. OfficeQA is static and read-only, and there is no synced-versus-unsynced or versioned-versus-unversioned control. The dual-view gain therefore cannot be attributed to version binding itself.

## Decisive evidence

- OfficeQA Pro contains **133 questions**. Dual versus artifact-only Pass@1 gains are **+12.1 / +10.1 / +8.3 points**, with paired-bootstrap half-widths 7.6 / 7.2 / 7.9 and p=.005 / .010 / .041.
- APEX-Agents includes **452/480 tasks**, excluding 28 API-dependent tasks. Dual versus parsed-only mean-rubric gains are **+4.7 / +5.5 / +9.2**, with half-widths 3.2 / 3.9 / 5.9 and p=.014 / .028 / .0002.
- On APEX, dual is only +1.0–4.0 above artifact-only and none of the three model comparisons reaches p<.05. **188/452** tasks score zero in every arm.
- The review axis covers only **57 file-editing tasks**. Diff-visible point estimates rise +2.5 / +8.5 / +3.8, but without confidence intervals or p-values; this is supporting evidence only.

## Cost and failure boundary

Reported API cost excludes Reducto/Mistral ingestion, background parsing, sandbox CPU, and startup. The production implementation is not public; the paper only plans sanitized code. Qualitative mechanism labels come from manual trace coding without annotator counts or agreement.

More importantly, the grader does not directly score whether workspace state transitions are correct. Dual access can improve benchmark outcomes while synchronization, edit-process, or final-artifact failures remain.

## Claim ceiling

Within a fixed SW-Agent harness, exposing parsed search and native artifacts together outperforms the more limiting single-view arm on 133 OfficeQA questions and 452 APEX tasks. This supports dual access, not a causal effect of content-hash versioning.

## Field-map consequence

This is an `early_signal` in **Execution & Transformation**. It brings intermediate state and deliverable artifacts into one workspace contract, but one paper without an isolated version-binding control does not change the stable map.
