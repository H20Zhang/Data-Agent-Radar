# ReAct-SQL：把 grounding 与 composition 拆成两个受控层

**中文** | [English](2608.22651.en.md) · [返回首页](../README.md) · [Research Library](../library/README.md)

[Paper](https://arxiv.org/abs/2608.22651) · **Importance: 4/5**

> **Research delta.** ReAct-SQL 的重要性不在“简单 ReAct 打败复杂 pipeline”这个 headline，而在同一 Gemini 2.5 Flash、同一 hints 与同一 judge 下的三阶段增量对照：一次性 raw SQL → raw-SQL ReAct → typed relational DSL。结果显示 EHR-SQL 的主要瓶颈是 grounding，而 BIRD 的主要瓶颈更接近 composition；两个组件的边际收益在两个 benchmark 上几乎反转。

## Problem

复杂 Text-to-SQL 系统通常把 schema linking、retrieval、candidate generation、self-correction 和多阶段 orchestration 一起加入。即使最终准确率提高，也难以判断收益来自“主动看数据”、结构化 query representation，还是更多 LLM 调用。真正需要隔离的是两个不同问题：模型是否找对表、列和值，以及找到后能否可靠组合出复杂查询。

## Mechanism

ReAct-SQL 只给模型 schema、问题和 DSL 文档，让它在 think → act → observe 循环中逐步构造查询。动作空间不是任意 SQL，而是 15 个 typed relational operations：12 个 Relation-building operations 加 3 个只读 probe。Relation 不可变，每次操作产生新的 handle；engine 在编译 SQL 前检查表、列和当前 Relation 的可见字段，并把 typed error、执行结果 preview 和持久 handle 返回给下一轮推理。

三个 probe——`probe_values`、`value_exists` 和 `sim_value_in`——负责直接观察数据库中的值和格式。DSL 则把 join、filter、aggregate、projection、window、materialize 等结构操作变成受检中间表示。模型自行停止，最多 15 turns；实践中 BIRD 平均 3.3 turns，EHR-SQL 平均 4.3 turns，单 turn 最多批量执行 8 个 tool calls。

## Closest comparison

最有因果解释力的不是 ReAct-SQL 对 CHESS / RSL-SQL / DSR-SQL 的横向排名，而是作者自己的三段 matched ablation：

1. **Baseline：** schema + question → 一次性 raw SQL。
2. **+ Iteration：** 保持 raw SQL action，只加入 ReAct execution-feedback loop。
3. **+ DSL：** 在 iteration 之上把 raw SQL action 替换为 typed relational DSL。

这三组都使用 Gemini 2.5 Flash、相同 hints 和相同 LLM judge，因此比跨系统比较更接近“grounding control vs composition control”的机制消融。

## Decisive evidence

- **EHR-SQL（n=934）**：baseline 45.9% → raw-SQL ReAct 72.2%，增益 **+26.23pp**，95% CI [+22.91,+29.66]，McNemar p≈10^-47；再加 DSL 仅到 73.9%，**+1.71pp**，CI [-1.07,+4.50]，p=.253。
- **Corrected BIRD mini-dev（n=498）**：baseline 78.5% → iteration 79.1%，仅 **+0.60pp**，CI [-3.41,+4.62]，p=.848；加入 DSL 后到 84.5%，相对 iteration **+5.42pp**，CI [+1.61,+9.24]，p=.006。
- 这组反转比 headline 排名更重要：EHR 的 value/schema grounding 对主动探查高度敏感，而 BIRD 在 grounding 已相对容易时，更受复杂 SQL composition 约束。它说明“是否需要 agentic iteration”不能脱离数据库分布判断。
- 横向结果仍有工程意义：ReAct-SQL 在 BIRD / EHR-SQL 分别为 84.5% / 73.9%，median latency 7.5s / 13.2s；但 RSL-SQL 在 BIRD 上更便宜，因此不能把它简化为全面效率胜利。

## Cost and failure boundary

循环最多 15 turns，但平均只用 3–4 轮；批量 tool calls 把多个 relation operations 合并到一次 LLM round trip。作者报告的平均 API cost 为 BIRD $0.0107/query、EHR-SQL $0.0166/query。Latency 右偏且受 provider / network 影响：BIRD 上 ReAct-SQL 的 median 只有 7.5s，但出现过 1837.3s 的极端 stall，因此“更快”应理解为当前环境下的 median comparison，而不是 tail-latency 保证。

另外，DSL 的工程复杂度没有消失，只是从 prompt pipeline 转移到 deterministic execution substrate：需要 Relation IR、compile-time validation、SQLite compilation、materialization 与 answer shaping。这仍然是有价值的系统边界，但不是“零基础设施”。

## Skeptical audit

最重要的替代解释有三项。第一，跨系统 baseline 并非完全 matched：RSL-SQL 使用 BIRD training-pair retriever，CHESS 在 EHR 上缺少 BIRD-style column descriptions，DSR-SQL 还替换了原始 backbone，因此“简单架构优于复杂架构”不能从横向表直接做因果归因。

第二，两个 benchmark 都用固定 LLM judge，而不是官方 strict execution-result equality；虽然所有系统共享 judge，endpoint 本身仍可能掩盖语义差异。第三，EHR-SQL 的 unanswerable subset 被排除，这项实验不测试澄清、拒答、safe-to-answer 或业务真实性。它证明的是 answerable Text-to-SQL 上的 grounding/composition control，不是完整 Data Agent correctness。

## Claim ceiling

现有证据支持：**在 answerable Text-to-SQL 中，主动数据库探查和 typed relational control 是两个可分离的控制层，而且哪个层更重要取决于 workload 的主要瓶颈。** 它还支持一个强 baseline 原则：在添加复杂 multi-stage / multi-agent orchestration 前，应先比较简单 adaptive probing + deterministic typed substrate。

现有证据不支持：iteration 普遍优于静态 schema linking、typed DSL 在所有数据库都必要、ReAct-SQL 在 enterprise-scale schema 上仍能取消 schema pruning、或 SQL answer correctness 等同于 business truth / artifact correctness。

## Field-map consequence

该工作以 `early_signal` 进入 **Planning & Semantic Interaction**，并连接 **Execution & Transformation**。它把“直接 SQL ↔ 中间计划”的张力进一步拆成 **grounding probe policy × typed execution representation**，但单篇证据不足以修改稳定 Field Map。
