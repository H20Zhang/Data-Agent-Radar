# SkillEffect：在工具分派前把数据程序降为有界执行

**中文** | [English](2608.17007.en.md) · [返回首页](../README.md) · [Research Library](../library/README.md)

[Paper](https://arxiv.org/abs/2608.17007) · **Importance: 4/5**

> **Research delta.** SkillEffect 不让模型生成的程序直接取得执行权，而是在 tool dispatch 边界重建一个受限中间表示，再调用经审计的有界实现；它把内存义务变成可检查的执行前条件。

## Problem

Agent 生成的 pandas、XLSX 或 Top-k 程序即使语义正确，也可能把整个输入载入内存，在单次工具调用的硬上限下失败。仅靠 prompt 要求“流式处理”不能保证最后提交的代码真的满足资源约束。

## Mechanism

每类受支持计算都注册一个 relation plugin：识别源程序、从不可变输入提取事实、构造 bounded IR、计算 arena 上界并声明后置条件。独立 checker 从提交程序重新建立这些关系；通过后，共享 runtime 才发放原子容量租约，执行 bounded VM，并在后置条件成立后发布输出。

控制边界是：

`agent program → recognize relation → rebuild bounded IR → reserve capacity → audited execution → verify → publish`

这个架构是可复用的，但 coverage 不是自动获得的：每个新关系仍需要人工编写并审计 plugin。

## Closest comparison

物理实验把同一任务、输入、verifier 和 cgroup cap 下的 eager direct execution 与 audited bounded implementation 对照。这个比较能回答“有界实现能否在相同外部内存上限下完成”，却不能把收益归因给 checker、lease 或 publication gate；论文也把它称为 operator-characterization reference。

更简单的部署方案是直接提供 typed bounded-tool API。论文显示，当平台拥有工具表面时，这种方案可以取得相同的受限执行，且不需要自动识别任意源程序。

## Decisive evidence

- 24 个 task–Skill 组合覆盖 6 类算子；hard-cap sweep 共 **1,296 个 cells**，其中 1,116 次执行、180 次拒绝。bounded access 的峰值内存比 eager 低 **3.75–24.25×**，中位数 **8.45×**。
- 在相同 cap 下，direct completion 为 **0 / 0 / 4 / 20 / 20 / 24（每档 24 项）**，bounded 为 **12 / 24 / 24 / 24 / 24 / 24**。
- 对 composition 已经生成正确 bounded plan 的 9 项任务，两条路径的 cap AUC 都是 **0.956**。额外覆盖来自其余已注册关系，而不是共享子集上的执行优势。
- 72 个自然语言 plans 中，25 次 verifier-valid attempts 只覆盖 10/24 个任务；lowerer 把其中 **5/10 direct success 提升到 10/10**，共 30/30 lowered repeats。
- checker 接受 **60/60** 个合法配置，并拒绝 **500/500** 个构造 mutation；这些是预设 mutation 类，不是开放部署错误分布。

## Cost and failure boundary

XLSX plugin 需要约 **476 行 relation-specific code**。认证和执行分别约 41.70 秒与 41.59 秒，因为两阶段都扫描 workbook；认证几乎把扫描工作翻倍。容量预留的中位 overhead 为 44.7%，最高 99.3%。模型 GPU 成本、plugin 审计工时与远程副作用不在预算内。

即使 48/48 tool executions 验证通过，外部 harness 的严格最终 JSON 也只有 **13/16**。因此 resource-safe execution 不能替代 artifact correctness 或 delivery validation。

## Claim ceiling

在六类人工审计、确定性、局部只读的数据工具关系上，checked dispatch 可以把被识别的 eager program 替换成语义受检的有界实现，并提高紧内存上限下的完成率。它没有证明任意 Agent code 都能被自动优化。

## Field-map consequence

该工作作为 `early_signal` 进入 **Execution & Transformation**。它为“生成代码”和“授予执行权”之间增加了明确的 resource-verification boundary，但单篇论文不足以改写稳定地图。
