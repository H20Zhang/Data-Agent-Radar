# BLIP: Turn provenance into an executable answer-reproduction witness

[中文](2608.25210.md) | **English** · [Home](../README.en.md) · [Research Library](../library/README.en.md)

[Paper](https://arxiv.org/abs/2608.25210) · **Importance: 4/5**

> **Research delta.** BLIP matters less as another way to return “relevant sentences” than as a stronger provenance contract: given the model's answer on the full input, find a smaller input subset on which the same model reproduces the same or an equivalent answer. That turns provenance from a relevance hint into an operational witness. The ceiling is equally important: it verifies **answer reproducibility**, not answer correctness, business truth, or provenance across a complete agent workflow.

## Problem

When an LLM performs document analytics, contract extraction, research QA, or other data processing, it normally returns an answer without a trustworthy execution trace to the source. Common provenance heuristics either retrieve embedding-similar passages or ask the model to report where its answer came from. Both can look plausible while missing the key test: if the rest of the input is removed, can the selected passages actually make the model reproduce the answer?

For Data Agents, this distinction separates several things that are often collapsed into “evidence”: citations, retrieved context, verification artifacts, and business-semantic correctness support different claims. BLIP establishes a narrower testable boundary: **is this input subset sufficient to reproduce this model's current answer?**

## Mechanism

The paper defines verifiable provenance as a subsequence `P` of the complete input text such that querying the same LLM with `P` alone returns the same or a semantically equivalent answer as the full input. It is minimal when removing any sentence from `P` changes that answer.

Enumerating all subsets is infeasible. BLIP therefore develops eight search strategies plus an adaptive strategy that selects among their strengths, and extends the machinery to return multiple minimal provenances. The systems idea is to use the LLM as an expensive membership/equivalence oracle while minimizing extra calls under an answer-preservation guarantee.

## Closest comparison

The closest simple controls are two families:

1. **Retrieval provenance:** embedding or top-k relevance selects passages that appear most related to the query or answer.
2. **Generated provenance:** the LLM itself marks or produces the source passages it believes support its answer.

Both can produce compact provenance, but neither automatically satisfies the counterfactual execution test that deleting all other input still preserves the answer. BLIP's delta is therefore not better citation ranking; it adds an executable answer-preservation check.

## Decisive evidence

- The paper evaluates **seven datasets** spanning real QA/document tasks and synthetic settings. The authors report that BLIP satisfies the answer-reproduction constraint and improves provenance accuracy by more than **30%** over the best baseline at comparable provenance size.
- Its adaptive/pruning search keeps the selected provenance to a small fraction of the original input while keeping total inference cost on the same order as the original full-input query in the tested workloads, showing that verifiable provenance need not imply exhaustive subset search.
- The multiple-provenance extension shows that one answer can have more than one sufficient input path. That makes an important interpretability point: a minimal provenance is not automatically a unique causal explanation.

The strongest support is therefore for a verification substrate: construct a replayable answer witness after the original LLM computation without changing the original model or task pipeline.

## Cost and failure boundary

BLIP is bolt-on rather than retrained, but it adds LLM calls after the original query to search and verify candidate subsets. Its cost result depends on search quickly shrinking the candidate space. The paper reports total adaptive-strategy cost comparable to the original full-input query, but this is still explicit verification budget and should not be conflated with a free citation layer.

More importantly, the current contract covers a **single LLM invocation**. Real Data Agents often execute retrieval → tool call → SQL/Python → intermediate state → review → retry. Reproducing one call from a smaller text subset does not reproduce tool state, database versions, program results, or cross-step dependencies. Workflow-level provenance remains open.

## Skeptical audit

First, the guarantee is answer preservation, not truth preservation. If the model's full-input answer is wrong, a provenance that reliably reproduces that wrong answer is still wrong; BLIP cannot replace Business Truth, a task oracle, or artifact correctness.

Second, minimality is model- and query-relative rather than a complete human causal explanation. Negation, counting, averages, and other non-monotone or aggregate queries can admit a small subset that happens to preserve the output while omitting the population or business conditions a real audit must retain.

Third, “equivalent answer” may itself require exact matching or an LLM judge. The paper checks near-deterministic behavior at low temperature, but open-ended generation still inherits the equivalence oracle's boundary.

## Claim ceiling

The evidence supports: **provenance for LLM-powered data processing can be upgraded from a relevance hint to an executable answer-reproduction witness without exhaustive cost on the tested workloads.** For Data Agents, this motivates measuring a distinct verification chain: `source relevance → answer-reproduction provenance → answer/business correctness`.

The evidence does not support treating BLIP provenance as factual support, a causal explanation, or business truth, nor does it establish provenance for multi-tool, multi-step agents with persistent state.

## Field-map consequence

This work enters **Verification & Recovery** as an `early_signal`. It operationalizes the existing separation between provenance and correctness with a replayable answer-preservation test, but one paper with a single-invocation scope does not change the durable Field Map.
