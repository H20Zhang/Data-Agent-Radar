# TRACE：在目录写入前分离证据发现与发布判断

**中文** | [English](2608.20844.en.md) · [返回首页](../README.md) · [Research Library](../library/README.md)

[Paper](https://arxiv.org/abs/2608.20844) · **Importance: 4/5**

> **Research delta.** TRACE 用 ScoutAgent 汇集 seller catalog、syndicated feed、图像和 identity-matched web evidence，再让 JudgeAgent 重新检查商品身份与属性支撑，最后通过 write policy 决定写入、阻断或人工复核。

## Problem

商品目录中的缺失属性常埋在非结构化内容或外部页面里。相似型号与变体会产生看似合理但属于另一商品的值，因此“提取成功”不能直接等于可发布的目录事实。

## Mechanism

category template 决定优先属性。ScoutAgent 搜集与归一化多源证据，输出候选值、引用、置信度以及 abstention/conflict 状态。JudgeAgent 独立重查身份与支撑，可追加搜索，并给出 PASS、FAIL、UNVERIFIED 或 UNCERTAIN。write policy 阻断低置信度与 FAIL，把 UNCERTAIN 送人工，但允许 PASS 或 UNVERIFIED 写入。

## Closest comparison

论文没有 Scout-only、no-Judge、单 Agent 或确定性 gate 对照。固定 Judge 后更换 Scout backbone 只比较模型 package；线上 A/B 只隔离“展示完整 TRACE 输出”的整体效果，不能归因给 JudgeAgent、多 Agent 分工、搜索或来源保存。

## Decisive evidence

- Grocery / Alcohol 人工集包含 500 个 SKU 与 2,497 个 SKU–attribute pair。Scout 的提取准确率为 **98.2%**，coverage 为 **74.7%**。这是 Scout 的准确率，不是 Judge 或多 Agent 的增益。
- 早期 binary Judge 的 PASS 值中 98.4% 被人工确认；但 Judge / human disagreement 里 87.8% 是 false rejection，促使系统后来改成四类 verdict。当前 verdict 与允许 UNVERIFIED 写入的策略没有单独做人工验证。
- Electronics / Home Improvement 的 4,990 个 pair 中，87.8% 有提取值，97.4% 被标成 PASS 或 UNVERIFIED。两类状态被合并为“Judge-supported”，不能视为 97.4% 准确率。
- 生产部署覆盖 3,100 万 SKU。五周随机 90/10 A/B 中，checkout conversion 相对提升 **0.48%**，95% CI [+0.04, +0.92]；missing/incorrect-item rate 相对下降 1.08%。这支持 end-to-end 产品效果，不隔离内部机制。

## Cost and failure boundary

每个 eligible SKU 至少一次 Scout 与一次 Judge 调用，两者都可能迭代 web search。论文只报告 Scout 模型的相对成本，没有绝对 token、延迟、web query、人工复核或美元成本；在 3,100 万 SKU 上，刷新与漂移成本不可忽略。

Scout 与 Judge 的主配置来自同一模型家族，存在相关错误。论文没有报告 identity-match accuracy、citation correctness、provenance completeness、calibration curve 或 human-review workload。线上实验也没有流量规模、随机单元、绝对基线率与按 vertical 分解。

JSON 与 write routing 可以规范执行；来源引用并没有被独立审计为完整或真正支撑。允许 UNVERIFIED 写入说明验证门槛仍是业务政策，而不是事实保证。

## Claim ceiling

证据支持一个大规模、多源、先提议再审查的 catalog transformation package，并显示整体部署改善了目录覆盖与购物指标。它不证明第二个 Agent、多 Agent 架构或 Judge policy 优于更简单的匹配控制，也没有跨类别验证 UNVERIFIED 写入的真实性。

## Field-map consequence

该工作作为 `early_signal` 进入 **Verification & Recovery**，并连接 Data Discovery & Grounding 与 Execution & Transformation。它把证据发现、候选转换和发布授权拆成三个边界；单篇 package-level 结果不修改稳定地图。
