# Polaris：面向对话式企业分析的动态多 Agent 编排

**中文** | [English](2608.14246.en.md) · [返回首页](../README.md) · [Research Library](../library/README.md)

[Paper](https://arxiv.org/abs/2608.14246) · **Importance: 3/5**

> **Research delta.** Polaris 把企业分析拆给 querying、visualization 与 reasoning 等专门角色，并通过 Dynamic Task Coordination 在线分配任务；当前证据说明这套系统能完成一组受控案例，但没有隔离 multi-agent coordination 相对更简单 controller 的净贡献。

## Problem

对话式 enterprise analytics 不是单次 NL→SQL：一个请求可能同时要求识别数据、生成查询、解释结果、制作可视化，并在中途结果出现后调整下一步。单一端到端调用容易把任务分解、工具执行与跨步骤状态混在一起，也很难判断哪一阶段出了错。

Polaris 研究的问题是：能否用角色分工与在线 task assignment 组织这条多阶段分析链。

## Mechanism

系统由多个专门 agent 承担 querying、visualization、reasoning 等职责，并用 Dynamic Task Coordination 根据当前任务与中间状态分派工作。

可以把控制流概括为：

`user request → decompose/assign → specialized tool work → coordinate intermediate outputs → compose analytic response`

这个机制扩大了系统的 orchestration capacity；但“使用多个 agent”本身不是效果归因。

## Closest comparison

最关键且目前缺失的 matched control 是：保持相同 base model、tools、prompts、上下文和总预算，只把多个角色合并为一个 controller，或关闭 Dynamic Task Coordination、使用固定 routing。

论文没有报告这样的 single-agent / DTC-off / component control，因此无法判断结果来自角色分解、更多模型调用、工具配置、prompt scaffolding，还是动态协调本身。

## Decisive evidence

Tables 1–2 报告了 **40 个 synthetic Airbnb cases**。三项指标严格限于 **retrieved-context semantic similarity、context precision、final-response answer relevancy**，分数依次为 **0.85 / 0.99 / 0.90**；按论文给出的阈值统计，通过率依次为 **100% / 100% / 92.5%**。

这些数字只支持一个有限结论：完整 Polaris package 在该合成案例集上的 retrieved context 与 final-response relevance 达到论文报告的阈值。它们不测 visualization quality，也不构成 multi-agent 优于 single-agent 的因果证据。

## What remains unproven

- 没有 matched single-agent baseline，也没有 DTC-off 或角色/component ablation；
- 没有把额外调用、token、latency 与 coordination overhead 纳入 cost-matched comparison；
- 40 个案例是 synthetic Airbnb setting，尚不能代表真实 enterprise schema、权限、脏数据、business-definition drift 与多轮需求变化；
- 没有系统性展示失败后的 recovery，以及错误 intermediate output 如何传播；
- 没有 causal validation；论文正文的证据边界是 **no code/reproduction link**，即未提供代码或复现实验链接，因而当前稿件本身不能支持组件级复核。

## Field-map consequence

Polaris 作为 `early_signal` 放入 **Planning & Semantic Interaction**：它提示 Data Agent 的研究对象正从“生成一次查询”扩展到“规划并协调一条多角色分析 workflow”；Execution & Transformation 是需要后续实证拆分的下游边界。

它暂不修改稳定领域地图，也不支持“multi-agent 更优”的判断。下一步需要 matched controller、DTC-off ablation、总成本、失败恢复和更真实企业任务上的证据。
